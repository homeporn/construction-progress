## Запуск на macOS

Пошаговая инструкция первого запуска, диагностики и восстановления:
[docs/macos_first_run.md](docs/macos_first_run.md).
Отдельный [чек-лист приёмки](docs/macos_acceptance_checklist.md) заполняется на каждом реальном Mac.
Для испытаний используйте отдельную сохраняемую базу:

```bash
./start.command --check --test-db
./start.command --prepare --test-db
```

Первая команда ничего не устанавливает и не изменяет SQLite; до подготовки она
может сообщить об отсутствии окружения. Вторая явно устанавливает зависимости
и запускает приложение. После остановки: `./start.command --test-db` — повторный
офлайн-запуск с теми же тестовыми данными. Рабочая база при этом не открывается.
Обычная диагностика рабочей базы без миграций: `./start.command --check`.
Режимы `--check` и `--prepare`, а также `--test-db` и `--db`, несовместимы.

Целевая конфигурация: официальный **CPython 3.13.12** с Python.org, обычная
GIL-сборка universal2. Заявленная поддержка macOS 10.13+ включает Catalina 10.15 Intel.
В перспективе используется та же база кода на macOS 13+ Intel/Apple Silicon.

По сообщению пользователя, предыдущая версия проверена на macOS. Ранее использовались Monterey и Safari.
Изменения этапов 4.1 и 4.2 проверены в Linux x86_64, CPython 3.13.5, SQLite 3.46.1; для них нужна повторная
приёмка на целевых Mac. Архитектура пользовательского Mac не уточнялась. Источники совместимости, версии
зависимостей и приёмка Catalina: [docs/compatibility.md](docs/compatibility.md).

1. Установите [CPython 3.13.12](https://www.python.org/downloads/release/python-31312/).
2. Откройте Terminal в каталоге проекта. Для первой подготовки с интернетом
   **явно** выполните:

```bash
chmod +x start.command
./start.command --prepare
```

Эта команда создаст `.venv`, если её нет, установит зафиксированные зависимости
и запустит приложение. Для следующего запуска:

```bash
./start.command
```

Откроется адрес вида `http://127.0.0.1:54321`. Порт назначается ОС и может меняться.
Если браузер не открылся, скопируйте напечатанный в Terminal адрес вручную.
Для завершения нажмите **«Завершить работу»** в боковом меню или **Ctrl+C** в Terminal.
Закрытие вкладки само по себе оставляет сервер работающим. Обрабатываются также
SIGTERM и, на macOS/Linux, SIGHUP при закрытии Terminal.

При обычном запуске зависимости проверяются без сети. Ничего не скачивается
и не обновляется. Существующая база не перезаписывается: применяются только
новые миграции, справочники не дублируются. Этажи и плановые нормативы автоматически
не создаются. Рабочая база — `data/construction_progress.sqlite3`.

Дополнительные варианты:

```bash
# Указать совместимый интерпретатор при создании окружения:
CP_PYTHON=/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13 ./start.command

# Не открывать браузер, выбрать другую базу или фиксированный локальный порт:
./start.command --no-browser --db /путь/к/базе.sqlite3 --port 5100

# Сохранённые консольные инструменты первого этапа:
./start.command --cli
./start.command --demo
.venv/bin/python -m scripts.init_db --db data/construction_progress.sqlite3
.venv/bin/python -m scripts.seed_catalog --db data/construction_progress.sqlite3
```

Если `.venv` несовместима, создайте новое окружение вручную совместимым Python.
Скрипт не удаляет существующее окружение. Для автономной установки перенесите
заранее подготовленные колёса нужной платформы и выполните:

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install --no-index --find-links /путь/к/wheelhouse -r requirements/macos_catalina.txt
./start.command
```

## Объекты и обновление до этапа 3.1

Откройте **«Объекты → Создать объект»**, введите название, уникальный код и количество
корпусов. Строки корпусов создаются в форме; коды и названия можно изменить до

Для существующей установки сначала остановите сервер. Сохраните каталог `data` и
обновите файлы приложения, не заменяя собственную базу. Первый обычный запуск
автоматически создаст проверенную копию в `data/backups/before-projects-*.sqlite3`
и применит миграцию 004. Прежние ID, события и планы останутся у объекта
«Строительный проект». `--check` по-прежнему ничего не мигрирует.
Подробная [инструкция обновления и восстановления](docs/workspaces.md).

## Автоматическое движение объёмов (3.1.1)

Ведомость, выполнение и подтверждение используют один `work_item_id`. В выполнении
показаны работы утверждённой версии с планом, фактом, подтверждением и остатком.
Положительная разность факта и подтверждения автоматически открывает работу во
вкладке **«Ожидают подтверждения»**. Полностью принятые работы остаются во вкладке
**«Все работы»** и журнале. Пользователь вводит каждый новый объём самостоятельно.

При плане 1000, факте 600 и подтверждении 450 показаны 60%, 45% и остаток подтверждения
150. Доступны частичное подтверждение, фильтры версии/даты/знаний и корректировки.
Остаток перепроверяется в транзакции; повторная отправка формы не создаёт дубль.
Аддитивная миграция 005 добавляет источник событий с предварительной проверенной
копией в `data/backups/before-event-flow-*.sqlite3`. Существующая база не пересоздаётся.
Подробная [инструкция сценария и обновления на Mac](docs/event_flow.md).

## Безопасное управление корпусами

В **«Настройках объекта»** доступно удаление свободного корпуса. Пустые этажи
удаляются вместе с ним только после отдельного подтверждения. Учётные позиции и
другие зависимости блокируют удаление: вместо него можно архивировать корпус.
Архив сохраняет планы, события и отчёты, исключая корпус из форм новых работ.
Восстановление возвращает прежний корпус и его связи. Новая миграция не нужна:
поле статуса уже существует. [Порядок работы и обновления на Mac](docs/building_management.md).

## Интеграция нарядов с объёмами — этап 3.3

В факте и подтверждении можно необязательно выбрать выданный наряд с этой работой.
Событие сохраняется один раз в прежнем журнале со ссылкой на строку документа.
Факт без наряда остаётся доступен; подтверждение можно связать с нарядом независимо
от источника факта. Карточка различает общие суммы работы и связанные суммы наряда.

Первый положительный связанный факт переводит наряд в «В работе». Сдача, проверка
строк и закрытие выполняются отдельными действиями с ответственным и историей.
Неполное задание можно закрыть с комментарием об остатке. Корректировки сохраняют
исходную связь, после проверки или закрытия показываются предупреждения и прежние
снимки решений. Превышение задания требует отдельного согласия и причины.

Аддитивная миграция 007 сохраняет события и миграции 001–006. Новых зависимостей нет.

## Первый рабочий сценарий

Аналитика этапа 4.0: новый раздел **«Аналитика»** содержит сводку объекта,
натуральные объёмы, графики динамики, отклонения, версионные пользовательские группы
и экспорт шести листов XLSX. Натуральные итоги разделены по коду и единице,
физическая готовность продолжает рассчитываться прежним нормативно-весовым ядром.
Кодификатор допускает пользовательскую справочную норму и предлагает её новой строке
черновика, не изменяя утверждённые нормы. Выработка за смену — отдельный справочный
калькулятор с явно введёнными численностью и часами.

Миграция 008 аддитивная, с проверенной резервной копией; 001–007 сохранены.
Новых зависимостей нет: графики — локальный SVG, XLSX — стандартный OOXML ZIP.
[Порядок работы и обновления на Mac](docs/analytics.md),
[результаты и изменённые файлы](docs/stage40_results.md),
[учебный Excel](docs/examples/analytics-school.xlsx).

1. Выберите объект в боковом меню (при необходимости создайте его в разделе **«Объекты»**).
   **Корпуса и этажи**: выберите корпус и добавьте этаж, например `-2`, `1`, `Тех`,
   `Кровля`. Значение порядка — отдельное целое число. Свободный этаж можно удалить;
   используемый этаж можно переставить, сохранив его идентичность.
2. **Ведомость объёмов**: выберите направление, добавьте учётную позицию из кодификатора.
   Создайте пустой черновик или копию утверждённой версии.
3. В строке позиции введите плановый объём и пользовательский норматив в чел.-ч/ед.,
   нажмите **«Сохранить»**. Пока версия черновая, показан предварительный расчёт.
4. Нажмите **«Утвердить версию»**. Во всех строках нужны положительные объёмы и нормы.
   Утверждённую версию нельзя изменить; последующие изменения выполняются в новом черновике.
5. **Фактическое выполнение**: выберите корпус, этаж, работу, дату и объём.
6. **Подтверждение**: выберите позицию, дату, объём, документ-основание и комментарий.
   Превышение подтверждения над накопительным фактом отклоняется без записи в базу.
7. **Сводка** и **История прогресса**: проверьте раздельные показатели, версию плана,
   трудоёмкость, остаток и причины предупреждений. Для истории задайте отчётную дату
   и момент отсечения знаний с часовым поясом. По умолчанию используются текущие дата/момент UTC.
8. Завершите приложение и запустите снова: позиции, версии и события сохранятся.

Уменьшение факта или подтверждения — отдельная запись с отрицательной дельтой и
ссылкой на исходное событие того же журнала. Исходные записи не редактируются и
не удаляются. Если уменьшение факта нарушает подтверждение, сначала исправьте
подтверждённый объём с документом-основанием. Проверяются также исторические границы.

Кодификатор содержит прежние **15 отделочных работ**, единица `м²`. Есть поиск по
кириллице, фильтры, добавление и редактирование неиспользуемых кодов. Используемая
классификация защищена от изменений, влияющих на историю. Нормативная база не выдумывается.

## Пример расчёта

Для учебного пользовательского ввода: план 1 000 м², норма 0,8 чел.-ч/м²,
факт 600 м², подтверждено 450 м²:

```text
Плановая трудоёмкость:       800 чел.-ч
Освоено по факту:            480 чел.-ч → 60%
Освоено по подтверждению:    360 чел.-ч → 45%
Остаток по факту:            400 м² / 320 чел.-ч
```

Норма в примере учебная, не справочная. Пример `--demo` работает в памяти.
При отсутствии данных интерфейс показывает «Нет данных». Для неверного расчёта
показаны статус «Ошибка» и причины; процент не заменяется нулём.

SQLite сохраняет объёмы и нормативы точными каноническими десятичными `TEXT`;
в расчётах используется Decimal. Суммы и произведения не округляются. Итоговые
бесконечные десятичные дроби представлены с 50 значащими цифрами; интерфейс форматирует
проценты только при отображении. Физические объёмы разных единиц не складываются.
Проценты этажей и работ взвешиваются по нормативной трудоёмкости.

Веб-маршруты не содержат формул прогресса и не выполняют SQL. Все записи идут
через существующие расширенные репозитории, отчёты — через расчётное ядро.

## Ограничения и дальнейшая работа

- Нужна отдельная приёмка на Catalina Intel и macOS 13+ Intel/Apple Silicon.
  Тест Linux/Chromium не доказывает совместимость с Safari.
- Это однопользовательское локальное приложение. Закрытие вкладки не останавливает сервер.
- Даты выполнения — календарные даты; регистрация и отсечение знаний используют UTC.
  Начало действия версии совпадает с моментом её утверждения. Отдельного effective_from нет.
- Сохранённые события неизменяемы. Отдельной сущности утверждения/подписания отчётов
  на этом этапе нет; недостоверные срезы помечаются ошибкой, а неверное подтверждение не сохраняется.
- Ввод ограничен 18 целыми и 9 дробными разрядами. Проверка полной истории при записи
  имеет квадратичную сложность; большие журналы требуют профилирования и оптимизации.
- Длинные таблицы пока без пагинации. Пакетный импорт реализован для персонала и
  табелей; нет резервного копирования из интерфейса и многопользовательских ролей.
- Для ручного переноса базы остановите приложение и копируйте SQLite-файл в бинарном виде.
  Произвольный SQL не является поддерживаемым API: межстрочные проверки Decimal
  выполняются репозиторием и ядром. Владелец файла может изменить его схему.

нагрузочные измерения, проектирование резервного копирования. Упаковка `.app`

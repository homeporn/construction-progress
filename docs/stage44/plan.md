# Этап4.4: локальные управленческие начисления

Полное ТЗ пользователя — источник требований. Никакого push, cloud deployment,
налогов/выплат/новой авторизации; Railway-задача остановлена в пользу4.4.
Схема до011; новое аддитивное расширение012. Исходные SHA/Git — baseline.json.

## Архитектура

- Условия оплаты и расценки: неизменяемые ревизии, полуоткрытые периоды
  [valid_from,valid_to), объект+подрядчик, стабильные employee/catalog IDs.
- Расчётный месяц: объект/подрядчик/year/month, явная нормачасов. Версии
  draft→calculated→submitted→approved→closed. Исправление утверждённого создаёт
  новую полную версию с разницей, не дополнительное повторное начисление.
- Calculation runs и строки неизменяемы даже при пересчёте черновика; текущая
  версия ссылается на последний run. Источники и условия фиксируются JSON+FK.
- Денежные суммы — integer minor units, вычисления Decimal, ROUND_HALF_UP.
  Поддержаны RUB/USD/EUR с двумя знаками. Валюты не суммируются друг с другом.
- Почасовая: часы утверждённой версии×ставка на дату. Оклад: каждый час
  интервала оценивается месячным окладом интервала / явно заданной нормой
  полного месяца. Норма не выводится из календарных дней. На нескольких
  объектах одинаковая месячная норма, только реальные часы данного объекта.
- Комбинированная: явно base_kind(hourly/salary/none), piece_enabled,
  bonus_kind(none/fixed/percent/performance), bonus_basis(base/piece),
  bonus_value,performance_threshold, fixed_supplement. Премия/доплата раз в
  период по последнему применимому условию; фиксированные месячные суммы
  распределяются между объектами по утверждённым часам (не удваиваются).
- Сдельная: отдельное явное сопоставление независимого подтверждения
  исполнителям. Не копирует атрибуцию факта4.3. Не меняет журналы.
  Подтверждение root+цепочка корректировок — банк доступного объёма.
  Технологическая операция имеет явно подтверждённый для начисления объём;
  полная расценка и операции одновременно по источнику запрещены.
- Piece previews требуют подтверждения. Резервирование в одной транзакции,
  идентификатор источника и остаток проверяются через все периоды. Старый
  approved и корректирующий draft одного периода резервируют максимум,
  не сумму. Распределение денег equal/hours/ktu/manual, exact largest remainder,
  равенство суммы целому начислению, stable employeeID tie break.
- Конфликты после изменения часов/подтверждения/атрибуций/условий выявляются
  по digest. Утверждённые суммы неизменяемы, нужен correction version.
- Премия performance только при полной персональной атрибуции и валидных
  распределениях4.3, никогда по одному наряду/численности.

## Разделение реализации

1. Главный агент: миграция012, payroll_repository (периоды/версии/runs/status/
   corrections/adjustments), интеграция и безопасность/сохранность.
2. Агент rules: payroll_money, payroll_rules_repository, payroll_calculator
   (термы/расценки/операции и источники/формулы), собственные тесты.
3. Агент piece: payroll_piece_repository (claims/previews/distributions/
   резервы/источники), собственные тесты.
4. Агент UI: routes/templates/navigation + восьмилистовыйXLSX, webtests.
5. После ядра: независимый review, полная регрессия, browserattempt,
   инструкция Safari и итоговый отчёт. Общая БД не используется в тестах.

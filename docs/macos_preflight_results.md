# Инженерный отчёт этапа 3 — 2026-10-17

Реальные Mac не использовались. Подготовлена воспроизводимая процедура приёмки;
статус совместимости Catalina, современных macOS и Safari остаётся непроверенным.

## Что изменено

- `start.command`: режим `--check`, явная подготовка окружения, русские ошибки,
  проверка принадлежности `.venv`, сохранение границ аргументов; без пустых массивов
  при `set -u`, что важно для Apple Bash 3.2.
- `scripts/check_environment.py`: сведения macOS/оборудования/Python/Rosetta,
  SQLite, точные версии и реальные импорты зависимостей, пути, read-only проверка
  базы и её миграций, проверка локального порта.
- `app/launch.py`: общие параметры запуска, локальная проба порта и безопасный
  выбор сохраняемой приёмочной базы с защитой от ссылок на рабочий файл.
- `main.py`: `--check`, `--test-db`, русская справка и сообщения; существующие
  консольные инструменты и обычный веб-запуск сохранены.
- `app/web/server.py`: перевод ошибки привязки Werkzeug в русское сообщение;
  отмена отложенного открытия браузера после остановки и обработка ошибки браузера.
- `.gitignore`: сохранённые при ремонте окружения не попадают в исходники.
- `tests/test_launch.py`: новые тесты диагностики и запуска.
- README, совместимость, инструкция первого запуска и отдельный чек-лист.

Расчётное ядро, репозитории, схема SQLite, миграции и бизнес-операции не менялись.
Новых зависимостей нет. Упаковка `.app` и Windows-версия не разрабатывались.

## Автоматические проверки

Исходные 142 теста прошли до изменений и сохранены. Итог: **174 теста проходят**;
32 новых случая покрывают архитектуры, диагностику, изоляцию тестовой базы,
аргументы запуска, отсутствие неявной установки и локализацию ошибок.

Испытательная среда: Linux x86_64, CPython 3.13.5, SQLite 3.46.1,
GNU Bash 5.2.37. Выполнены pytest, `bash -n start.command`, compileall и проверка
локальных ссылок документации. Эмуляция ответов sw_vers/sysctl не засчитывается
как аппаратная приёмка. Импорты библиотек реально проверены на Linux, не Mach-O.

## Реальный запуск процессов на Linux

На отдельной временной копии исходников по пути `/tmp/Construction Progress приёмка ...`
выполнены реальные команды `start.command` из другого каталога:

- `--check --test-db` до появления приёмочной базы: код 0, база и её каталог не созданы.
- Создание этажа, позиции и плана, утверждение, факт 600 и подтверждение 450 через
  HTTP-формы локального сервера: получены 60% / 45%.
- Сохранение после остановки кнопкой и ещё трёх запусков с SIGINT, SIGTERM, SIGHUP:
  код процесса 0, сокет закрыт.
- После перезапусков: корпуса 3, коды 15, этаж 1, позиция 1, версия 1, событие
  факта 1, событие подтверждения 1. Дубли не созданы; integrity_check `ok`, FK-ошибок 0.
- Контрольная сумма имитирующего рабочие данные SQLite-файла не изменилась.
- Диагностика сохранённой тестовой базы не изменила её контрольную сумму.
- При занятом порте: диагностический код 1; запуск — код 2 с русской ошибкой,
  без traceback и без завершения владельца занятого порта.
- Внешние TCP-соединения Python заблокированы проверочным перехватчиком. Попыток
  внешних подключений не было; обычные команды не вызывали pip.

Рабочая база пользователя не открывалась для записи в испытаниях. Все тесты pytest
выполнены в песочнице без сетевых разрешений; реальным серверным процессам были
предоставлены локальные сокеты. Это проверка отсутствия интернет-зависимости
приложения на Linux, не физическое отключение сети на целевом Mac.

Пример реального вывода диагностического режима на временной Linux-копии:
[stage3_diagnostic_example.txt](stage3_diagnostic_example.txt). В нём временные
пути; это не отчёт о приёмке Mac.

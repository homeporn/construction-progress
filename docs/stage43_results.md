## Что проверено

Контрольный сценарий: пять синтетических работников ×8ч =40ч;100м² ×0,5=50
нормативных часов. Явная атрибуция бригаде даёт2,5м²/чел.-ч и125% выполнения нормы.
Образец XLSX сформирован на временной базе, без ФИО/контактов в выгрузке.

Проверены дробные и нулевые часы, частичные распределения, откат bulk при ошибке,
повторные POST, устаревшие источники/ревизии/состав бригады, отрицательные значения,
неутверждённые табели, история версий/момента знания, конфликты8→6ч и100→90м²,
поэтапное исправление конфликтов, смена работодателя, явная атрибуция без наряда,
независимое подтверждение, фильтры, архивные корпуса и неизменность расчётов.

Детерминированные проверки на двух SQLite-соединениях воспроизводят конкурентную
попытку распределить один остаток дважды. Время знания назначается после writer
lock, так что второй запрос не исключает уже сохранённые операции из проверки.
Старые распределения не могут незаметно сменить подрядчика при изменении карточки
работника; отозванная атрибуция не становится ложной нулевой выработкой.

Новая миграция проверена на повторном применении, Backup API, сохранении ID/старых
столбцов, совпадении60%/45%, artificialSQLошибке и намеренном изменении старых
данных: откат проходит, проверенная копия остаётся. SQL FK и integrity_check — без ошибок.

Во время первого интеграционного прогона обнаружен один регрессионный тест меню:
после добавления восьмой группы перестал отклоняться массив из восьми повторов.
Исправлена причина (проверка уникальности), проверка сохранена и проходит.

## Средний профиль

Создана новая отдельная временная база:3объекта,10корпусов,10 000позиций,
50 000фактов +50 000подтверждений,500работников,15 000записей табеля.
Размер71 643 136байт (68,32MiB). Измерение относится к выбранному первому объекту,
а не к одновременной выдаче всех трёх объектов одним отчётом.

Финальная проекция с дневной динамикой:2прогрева +10повторов, среднее**1,18с**,
p95**1,32с**,14SQL-запросов на проекцию, processpeak**115,2MiB**.
Сохранение отдельного распределения на той же базе:около**3мс**.
[Все значения и условия](stage43/medium_results.json).

Это Linux-измерения в общей среде одновременно с регрессией, а не обещание скорости
на Mac. Размер SQL-выборки не растёт числом строк отчёта за счёт N+1: планы,
метаданные, имена и назначения выбираются пакетно. POST отдельной строки и история
не вызывают полную аналитическую проекцию. Чтение аналитики всё ещё требует
проектной выборки цепочек событий; это не полностью потоковый расчёт.

До/после аналитического распределения сравнен отпечаток физического прогресса:
значения совпали. Весь этап4.2.1 повторно не запускался.

Воспроизведение в отдельной базе на Mac из корня проекта:

```bash
.venv/bin/python tools/performance/generate_dataset.py \
  --profile medium --output /tmp/cp43-medium-check.sqlite3
.venv/bin/python -m pytest tests/test_labor_allocations.py \
  tests/test_labor_concurrency.py tests/test_labor_migration.py \
  tests/test_labor_productivity_analytics.py tests/test_labor_productivity_web.py -q
```

Генератор отказывается перезаписывать существующий файл. Средний объект открыть
только явным `--db /tmp/cp43-medium-check.sqlite3`, не подменять рабочую базу.

## Браузер и скриншоты

Сделана реальная попытка запуска `/usr/bin/chromium` через Playwright с экраном
1366×768. Sandbox запрещает локальные сокеты; Chromium завершается до открытия
страницы с crashpad `setsockopt: Operation not permitted`, `SIGTRAP`.
Повтор с отключением crash reporter не устранил ограничение. Shared desktop/
computer-use tools в среде не предоставлены. Неудавшийся запуск не является
проверкой JavaScript, сетевых запросов или компоновки.

Скрипт `tests/browser_stage43.py` сохраняет фактические попытки и backend-проверки
отдельно в `docs/stage43/browser_results.json`. Скриншоты не созданы. Проверки
маршрутов/форм/CSRF/экспорта выполнены через Flask test_client; это не замена Chromium.

## Обновление существующей установки на Mac

1. Завершить приложение кнопкой или Ctrl+C и дождаться остановки.
2. Сохранить проверенную копию SQLite штатным Backup API. Если используется
   Windows launcher — его `--backup`; для Mac можно выполнить Python ниже.
3. Обновить программные файлы, **сохранив каталог data**, пользовательские backups,
   exports и настройки установки. Не подменять рабочую базу синтетической.
4. Запустить `./start.command`. Новых runtime-зависимостей для Mac нет.
5. Дождаться миграции011. При ошибке не продолжать работу; сохранить показанную
   предмиграционную копию. Проверить свои объекты, табели, факты и подтверждения.

Пример Backup API после остановки приложения (не перезаписывает прежние копии):

```bash
.venv/bin/python - <<'PY'
from app.config import DEFAULT_DB_PATH
from app.database import connect, backup_database
if not DEFAULT_DB_PATH.is_file():
    raise SystemExit('Рабочая база не найдена — сначала проверьте её реальный путь')
db = connect(DEFAULT_DB_PATH)
try:
    print(backup_database(db, label='before-stage43-manual'))
finally:
    db.close()
PY
```

Если запуск использует отдельный `--db`, в примере нужно указать этот же путь.
После записи011 не возвращаться к старому приложению, которое её не поддерживает.
Возможность переноса той же схемы Windows не означает проверенную нативную сборку:
архив W1 Build Kit остаётся прежним снимком до4.3 и не объявляется новой поставкой.

На отдельной тестовой копии: создать «Школа», подрядчика и бригаду5человек;
утвердить40ч на день; зарегистрировать100м² без наряда с нормой0,5;

через просмотр и подтверждение; назначить100м² бригаде; проверить50/40/125%/2,5.
Затем разделить часы на24+16 по двум работам, проверить остатки, исправить
табель8→6 и факт100→90, убедиться в конфликте и снятии KPI. Исправить распределения,
просмотреть старый момент знания, выгрузить семь листов Excel, переключить объект.
Проверить1366×768, SafariConsole и отсутствие внешних запросов.

## Ограничения

- Нативная приёмка Mac/Safari и Chromium в разрешающей среде не выполнена.
- Нет проверяемой связи независимых подтверждений с исполнителем: их показатели
  в подтверждённом режиме неизвестны; атрибуция факта не копируется автоматически.
- При фильтре корпуса посещаемость всё ещё объектная: без распределения нельзя
  определить, в каком корпусе были нераспределённые часы.
- Полнота данных показывается явно; сравнение неполных исполнителей предварительное.
- Персональная одновременная работа проверяется по утверждённым часам, но интервалы
  начала/окончания смен табель4.2 не хранит — их пересечения не выдумываются.
- Подтверждённые часы/объёмы и аналитические ревизии не являются зарплатой или
  юридически значимой подписью. Следующий этап не реализуется.

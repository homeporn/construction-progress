# W1.0 — план и решения

Основание: подробное ТЗ пользователя W1.0; работа в существующей незакоммиченной
копии, без отката, push, CI и изменения расчётов. Исходное состояние и SHA-256 —
`baseline.json`; исходная регрессия: 829 passed, 95,58 с.

Архитектура: существующий Flask → Waitress на 127.0.0.1 с атомарным bind(0).
Portable-профиль рядом с EXE; отдельный пользовательский каталог можно указать
через --data-dir. Ресурсы — _internal, данные — data/backups/exports/logs профиля.
Консоль EXE и существующая CSRF-защищённая кнопка завершения вместо новой UI.
ОС-блокировка и аутентифицированная HTTP-проверка отличают живой экземпляр
от устаревшего файла. Блокировка удерживается до завершения всех запросов.

Рассмотрены onefile и тяжёлая панель/трей: не нужны и противоречат предпочтению
onedir и простого контроллера. Существующий macOS launcher сохраняется.

## Проверки риска

Unicode/пробелы и независимость от cwd; read-only папка; повреждение и более
новая схема БД; сбой миграции без запуска сервера; повторный процесс во время
миграции; ложный health endpoint; остановка при активной транзакции; ресурсы
frozen и отсутствие пользовательских данных в ZIP.

## Ограничения среды

Доступна Linux x64, Windows runner/PowerShell/Wine не обнаружены. Ни Windows
проверка, ни Windows EXE не заявляются без фактического запуска. Сборка на Windows
потребует CPython x64 и build.ps1; пользователю готового EXE Python не нужен.

Повторная регрессия: 857 passed, 7 skipped (запрет loopback socket sandbox),
98,97 с. Блокировка ОС проверена между настоящими процессами на Linux;
аутентифицированная HTTP-проверка и Windows msvcrt остаются нативной приёмкой.

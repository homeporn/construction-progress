# Этап4.5 — исполнение нарядов и перенос остатков

Модуль расширяет существующие наряды-задания. Прежние URL, карточка, печать,
выдача и модель статусов сохранены. В разделе «Производство» добавлена страница
«Контроль нарядов». Новый наряд не становится обязательным для факта,
подтверждения, табеля, производительности или начислений.

## Архитектура

- `WorkOrderRepository`: прежний документ, черновик, состав и снимок выдачи.
  Внутренний `_save_draft` позволяет создать дочерний документ в той же
  транзакции, что и резервирование остатка.
- `WorkOrderWorkflowRepository`: существующие действия сдачи, проверки и закрытия.
  Закрытие проверяет реальные решения об остатках, а не наличие комментария.
- `WorkOrderControlProjection`: общая точная проекция журналов и решений для
  карточки, команд, цепочки и аналитики.
- `WorkOrderTransferRepository`: перенос, безопасная отмена, списание и его
  отмена, явное сопоставление независимых событий.
- `WorkOrderControlRepository`: реестр с серверными страницами, фильтры и аналитика.
- `work_order_control_xlsx.py`: семь листов через существующий локальный OOXML writer.

Новой таблицы нарядов или второго журнала выполнения нет. Миграция013 добавляет
только производственные решения и их связи. Нормативы, планы, факт,
подтверждения, табели, распределения4.3 и начисления4.4 команда переноса не меняет.

## Показатели строки

Обозначения: Q — выданное количество из неизменяемой строки; F — чистая сумма
достоверно связанных событий факта; C — чистая сумма связанных подтверждений.
Цепочки корректировок учитываются точно через Decimal. Факт и подтверждение
считаются отдельно; общий факт позиции не присваивается наряду автоматически.

T — сумма активных переносов; R — часть T в дочерних черновиках; S — часть T
в уже выданных дочерних нарядах. W — действующее явное списание.

| Показатель | Формула / смысл |
| --- | --- |
| Исходное поручение | Q; перенос его не уменьшает |
| Учтено выполнение | F |
| Подтверждено | C; не заменяется величиной F |
| Невыполненная часть исходного задания | `max(Q−F,0)` |
| Неподтверждённая часть исходного задания | `max(Q−C,0)` |
| Зарезервировано | R; получатель ещё черновик |
| Перенесено всего | T=R+S; отменённые переносы исключены |
| Передано выданному получателю | S |
| Доступно для нового переноса | `max(Q−max(F,C)−T−W,0)` |
| Открытый объём цепочки в этой строке | `max(Q−C−T−W,0)` |
| Неразрешённый остаток для закрытия | `max(Q−C−S−W,0)` |
| Объём с определённым исходом | `max(0,min(Q,C+S+W))` |
| Превышение факта / подтверждения | `max(F−Q,0)` / `max(C−Q,0)` |

Разница между открытым объёмом и условием закрытия намеренная: черновик уже
резервирует объём, но ещё не является выданным поручением. До выдачи получателя
родитель нельзя закрыть только ссылкой на этот черновик.

Безопасная база переноса использует **max(F,C)**. При Q120/F110/C100 доступно10,
а не20: уже выполненные, но ещё не принятые10 нельзя поручить повторно. Общий
непривязанный факт на том же этаже этот остаток не уменьшает. В формуле нет
денег, табельных часов, нормативов или состава бригады.

## Остаток к приёмке и сопоставление

Независимое подтверждение, связанное с НЗ, не устанавливает связь с конкретным
фактом. Поэтому F−C не выдаётся за точный остаток к приёмке.

В карточке можно явно сопоставить **корневое событие факта и корневое событие
подтверждения той же строки**, указав количество и основание. Редакция хранится
отдельно, источники остаются неизменными. Разрешены несколько сопоставлений,
но суммарное количество по каждому корню не превышает его чистой ёмкости с
корректировками. Изменение требует текущей редакции и причины; нулевая новая
редакция снимает прежнее сопоставление.

- F=0: связанного факта, ожидающего приёмки, нет.
- C=0: весь положительный связанный F ожидает приёмки.
- При полном действительном сопоставлении C с F: остаток=`max(F−сопоставлено,0)`.
- При наличии несопоставленных подтверждений: **«Требуется сопоставление»**,
  числовое значение не подставляется.

Если корректировка сделала старое сопоставление недействительным, показывается
конфликт. История не обрезается и количество не уменьшается автоматически.
Нельзя использовать общий непривязанный факт для искусственного выполнения НЗ.

## Создание переноса

В существующей карточке нажмите «Перенести остаток» и отметьте строки.
Укажите количества, дату и время новой смены, подрядчика, исполнителей,
обязательное основание и при необходимости комментарий.

Команда повторно проверяет доступный объём под SQLite `BEGIN IMMEDIATE` и
создаёт **один новый черновик** с наследуемыми строками. Номер назначается
только отдельной выдачей. Полный или частичный перенос сразу расходует резерв.
Две команды по15 из остатка20 не могут создать30.

Пример: Q120/C100/F100 → перенос20. Родитель сохраняет120, его доступный
остаток становится0, ребёнок содержит20. После выдачи ребёнка R становится0,
S становится20. Перенос не является новым выполненным объёмом.

При переносе40 частями25 и15 образуются две ветви. Их сумма ограничивается
исходной ёмкостью. Каждому новому документу можно назначить другую бригаду;
старый состав и снимок выдачи не переписываются.

Новая строка использует действующий утверждённый план для **той же учётной
позиции**, сохраняя код и единицу. Если позиция исключена из текущего плана,
архивна или единица несовместима, перенос отклоняется. Новая смена не может
предшествовать исходной. Подрядчик и работники проходят прежние правила
принадлежности объекту и назначения; обхода ограничений модели нет.

Заголовок, состав и примечания наследуемого черновика можно менять. Его
количества, позиции и ID строк сохраняются, в форме они заблокированы.
Для другого количества отмените безопасный перенос и создайте новый.
При выдаче вновь проверяются ёмкости всех активных предков. Поздний исходный
факт или корректировка могут сделать ранее зарезервированный черновик
недопустимым; выдача тогда блокируется с объяснением.

Снимки исполнителей на момент переноса и выдачи сохраняются. Это поручение,
а не регистрация рабочего времени: часы, трудозатраты и начисления не копируются.

## Отмена и списание

Отмена переноса добавляет отдельное событие с причиной. Исходная операция и
строки сохраняются; дочерний черновик становится отменённым, исходный резерв
освобождается. Та же защита работает через прежнюю кнопку отмены черновика.

Если ребёнок уже выдан, содержит зависимые операции или последующие переносы,
отмена исходного переноса запрещена. Автоматического удаления выданного
документа нет. Его остаток разрешается дальше обычным подтверждением,
последующим переносом или допустимым списанием.

Списание — отдельное решение об отмене невыполненного поручения. Оно требует
количества и причины и ограничено **доступной невыполненной частью**. Уже
зарегистрированное выполнение не списывается вместо настоящей приёмки.
Отмена списания создаёт обратное событие; старое решение не редактируется.
Если такое решение относится к уже закрытому документу, новая проекция
показывает необходимость урегулирования, не меняя старый статус и снимок.

## Жизненный цикл и закрытие

Сохраняется последовательность:

`draft → issued → in_progress → submitted → accepted → closed`.

Положительный факт по-прежнему может начать работу автоматически. Наряд без
связанного факта, у которого **полностью определён исход всех строк**, можно
явно сдать на проверку: регистрируются in_progress и submitted, без фиктивного
события факта. Это позволяет завершить полностью переданное или отменённое
поручение.

Закрытие требует:

1. Статус accepted и актуальную проверку всех строк.
2. Нулевой неразрешённый остаток: `Q−C−S−W≤0`.
3. Отсутствие конфликтов резерва, списаний, сопоставлений и активных предков.
4. Для превышения поручения — явное замечание проверяющего по строке.

Комментарий «остаток перенесён» без операции переноса больше не разрешает
закрытие. Подтверждение в статусе accepted теперь можно зарегистрировать через
прежний журнал; после него нужна повторная проверка перед закрытием. Новые
факты в submitted/accepted/closed не разрешаются прежними правилами; корректировки
сохраняют исходную связь и историю.

Решения, события и изменение состояния резервирования входят в отпечаток
проверки. Выдача дочернего черновика требует перепроверить родителя; обычный
переход уже выданного ребёнка submitted→accepted не делает его собственное
решение устаревшим. Нельзя указать время закрытия раньше последующего изменения
источника, контроля или состояния активного предка.

Старые закрытые документы012 не меняются при миграции. Их прежние решения и
снимки сохраняются. Если по новой проекции есть остаток или появились поздние
корректировки, он виден в реестре расхождений. Автоматического отката статуса нет.

## История, цепочки и даты

Каждый перенос хранит источник/получателя, ID строк, количество, единицу,
время регистрации, дату новой смены, основание, комментарий, ключ команды и
исторические сведения об исполнителях. Личность инициатора не объявляется
проверенной: система пользователей пока отсутствует.

Карточка показывает связанные НЗ с переходами по ссылкам, ветви, отмены,
сопоставления и списания. В цепочке120→20→5 первоначальное поручение равно120,
а при подтверждениях100 и15 открыто5. Наследуемые20 и5 не увеличивают исходное
поручение. Каждое независимое подтверждение учитывается один раз через его
собственную строку. Разные коды и единицы остаются разными группами.

Для истории используются дата среза и отсечение знаний UTC. Корректировки
отбираются по бизнес-дате и времени регистрации; решения контроля и статусы —
по моменту, доступному на срезе. Будущие отмены и номера ещё не выданных детей
не попадают в прошлый срез. Выданные снимки и старые решения не переписываются.
Текущие реквизиты редактируемого черновика не являются системой версий всех
его полей; первоначальный замысел переноса дополнительно хранится в снимке
самой операции.

## Реестр и аналитика

Реестр отображает50 нарядов на странице. Структурные фильтры используют
SQL COUNT/LIMIT/OFFSET. Фильтры по вычисляемому остатку и расхождениям обрабатывают
точные серверные пакеты кандидатов, затем возвращают одну страницу. Весь журнал
в HTML не выгружается. Запросы с большим числом ID разбиваются на пакеты,
совместимые с SQLite с лимитом999 параметров.

Фильтры: текущий объект, корпус, подрядчик, историческая бригада, даты смен,
статус, остаток, перенос, незакрытые документы и расхождения. «Незакрытые»
означает статус, а не только наличие объёма: полностью выполненный accepted
также ещё не закрыт.

Контроль отдельно показывает выполнение по факту, полное подтверждение,
определённый исход поручения, открытые и закрытые документы. Перенос и списание
не объявляются выполнением. Натуральные итоги группируются по коду и единице.
Дневная динамика факта и подтверждения использует даты первичных событий,
а первоначальное поручение — дату исходной смены без повторения дочерних объёмов.

Если в документе несколько бригад без достоверного разбиения объёма, применяется
общее обозначение состава «Б1, Б2». Полный объём не присваивается каждой бригаде.
Граф цепочки показывается целиком даже при выборе связанного дочернего документа;
для его баланса нужен контекст предков. Другие объекты в выборку не входят.

Просрочка **не определяется**: дата смены не является установленным сроком
завершения. Нового планирования смен или календарно-сетевого планирования нет.

## Excel

Кнопка на экране контроля формирует локальный XLSX:

1. Реестр нарядов.
2. Контроль исполнения по строкам.
3. Неразрешённые остатки.
4. Переносы и отмены, источники и дочерние документы.
5. Балансы цепочек.
6. Расхождения.
7. Первичные источники, решения списания/сопоставления и необходимые метаданные.

Сохраняются объект, фильтры, дата и UTC-срез, статусы, код, единица, исполнители,
количества, ID источников и связей. Decimal записывается числовой ячейкой, даты
типизированы. Текст пользователя остаётся текстом, включая строки с `=`.
Длинные снимки исполнителей разбиваются без потери на пронумерованные части
на седьмом листе с исходной ячейкой и SHA-256. Количество листов остаётся семь.
При превышении15 значащих цифр действует дополнительное точное текстовое
представление существующего writer — это ограничение самого Excel.

## Миграция013 и транзакции

Добавлены шесть таблиц:

- `work_order_control_commands`: идемпотентность с отпечатком параметров;
- `work_order_transfers`: источники и новые дочерние черновики;
- `work_order_transfer_lines`: происхождение каждой наследуемой строки;
- `work_order_transfer_cancellations`: неизменяемая история отмен;
- `work_order_resolutions`: списания и отдельные обратные решения;
- `work_order_volume_matches`: редакции явного сопоставления событий.

Используются прежние ID нарядов и строк. FK, уникальности, проверки объекта,
кода/позиции/единицы, защита от циклов и неизменяемость наследуемых количеств
дополняют проверки репозитория. API всегда создаёт новый дочерний черновик,
поэтому перенос назад в предка или в выданный документ недоступен.

Под `BEGIN IMMEDIATE` повторно читается ёмкость и атомарно создаются документ,
контрольные строки и результат команды. Повтор ключа с теми же параметрами
возвращает прежний результат; другой запрос с этим ключом получает конфликт.
Промежуточный результат команды финализируется один раз внутри той же транзакции
и не виден другим соединениям. Опубликованные решения не редактируются.
busy_timeout и journal_mode не изменены.

Перед обновлением существующей012 штатный migrate создаёт проверенную копию
SQLite Backup API `before-work-order-control-*`. Миграция013, проверки всех
старых столбцов и маркер применяются одной транзакцией; ошибка откатывает DDL
и изменения триггеров. Проверяются integrity_check и foreign_key_check.
Миграции001–012 не изменялись.

## Ограничения

Это локальная система без пользователей/ролей. Сохранены CSRF, Host/Origin и
контекст объекта. Доступ к компьютеру, SQLite, копиям и экспортам защищается ОС.
Облачная публикация, фиктивная авторизация, пересчёт зарплаты и новые сборки
Mac/Windows не выполнялись.

За один перенос допускается до1000 строк. Карточка и исходная форма сохраняют
прежнюю архитектуру широких таблиц; аналитические таблицы экрана ограничены50
группами, полная выборка доступна в Excel. Реальная браузерная и Mac/Safari-проверка
описаны отдельно в [результатах](stage45_results.md). Исторические ограничения
4.2.1, Windows W1.0 и браузерной приёмки4.4 не отменяются этим этапом.

а проверенная предмиграционная копия сохраняется.

## Обновление существующей установки на Mac

1. Завершите старый сервер кнопкой либо Ctrl+C. Сохраните прежний каталог кода.
   Обновляйте исходники, **сохраняя свои `data/` и `.venv`**. Не заменяйте базу
   файлом из репозитория/демо. Новых библиотек устанавливать не требуется.
2. Откройте Terminal в каталоге установки. Пути с пробелами и кириллицей заключайте
   в кавычки:

```bash
cd "$HOME/Downloads/construction-progress"
./start.command --check
```

Диагностика ничего не мигрирует и не устанавливает. Проверьте показанный путь
к базе и ожидающие миграции. Для нестандартной базы добавляйте во все команды
`--db "/полный/путь/рабочая база.sqlite3"`.

3. При необходимости сделайте дополнительную ручную согласованную копию:

```bash
.venv/bin/python - <<'PY'
from pathlib import Path
from app.database import connect, backup_database
p = Path('data/construction_progress.sqlite3').resolve()
if not p.is_file():
    raise SystemExit('База не найдена; проверьте путь')
db = connect(p)
try:
    print(backup_database(db, label='manual-stage42'))
finally:
    db.close()
PY
```

4. Сначала выполните приёмку 4.1 и 4.2 в отдельной сохраняемой базе:

```bash
./start.command --test-db
```

После проверки завершите сервер. Для обновления и обычной работы:

```bash
./start.command
```

Браузер откроется на `127.0.0.1` со свободным портом. Для базы 009 до миграции
автоматически создаётся `data/backups/before-timesheets-*.sqlite3`. Для более
старой схемы имя отражает первую ожидающую миграцию. Каждая миграция фиксируется
отдельно; успешно применённые предыдущие миграции при сбое следующей сохраняются.
Обычный запуск не обращается в интернет.

5. После завершения сервера проверьте целостность без записи:

```bash
.venv/bin/python - <<'PY'
import sqlite3
from pathlib import Path
p = Path('data/construction_progress.sqlite3').resolve()
with sqlite3.connect(p.as_uri() + '?mode=ro', uri=True) as db:
    print(db.execute('PRAGMA integrity_check').fetchall())
    print(db.execute('PRAGMA foreign_key_check').fetchall())
    print(db.execute('SELECT name FROM schema_migrations ORDER BY name').fetchall())
PY
```

Ожидается `ok`, пустой список FK-ошибок и маркер 010. При ошибке не удаляйте базу,
не сбрасывайте маркеры и не запускайте повторную инициализацию вручную. Сохраните
ошибочный файл отдельно, устраните причину (права/место/версия кода), повторите
`--check` и обычный запуск. Для отката используйте **копию** проверенного
предмиграционного файла с прежним кодом, не перезаписывая единственный оригинал.
Старый код не должен открывать схему 010. Перед исследованием копии можно выполнить:

```bash
./start.command --check --db "/полный/путь/копия до обновления.sqlite3"
```

## Ограничения

Нет пользователей/ролей и удостоверенной подписи, шифрования базы или резервных
копий. Персональные данные не передаются наружу; защитите компьютер, SQLite и
копии организационно. Это локальное однопользовательское приложение.

Без времён начала/окончания доступен общий суточный предел, но не доказательство
отсутствия пересечений смен. Черновики резервируют время — оставленный черновик
может блокировать ввод на другом объекте, пока его не исправят/отменят.
Пропущенная ячейка не считается подтверждённой неявкой. Бригада строки — снимок
начала доступности месяца; историю состава для массового заполнения выбирают
отдельно. Большие матрицы/реестры пока без пагинации. Предпросмотры и аудит
хранятся локально без автоматического срока очистки. Дополнительные коды можно
добавлять при обслуживании SQLite; отдельной формы редактирования кодов пока нет.

Не реализованы зарплата, ставки, табель из наряда, автоматический строительный
факт, производительность, недельное/сетевое планирование, интеграции с внешними
планировщиками и контроль переносов нарядов. Этап 4.3 и push не выполнялись.

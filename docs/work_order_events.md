# Факт, подтверждение и наряды — этап 3.3

Наряд — необязательное основание регистрации объёмов. Ведомость, выполнение,
подтверждение и наряд используют одну учётную позицию `work_item_id`.
Объёмы хранятся только в прежних `fact_events` и `confirmation_events`.
Задание смены не изменяет план ведомости или физический прогресс.

## Регистрация объёмов

1. Выберите объект и утвердите ведомость. При необходимости создайте и выдайте
   наряд по [инструкции создания документов](work_orders.md).
2. В **«Фактическом выполнении»** выберите работу, дату и новый объём.
   **«Наряд-задание (необязательно)»** предлагает документы текущего объекта,
   содержащие эту позицию. Подсказка показывает задание, связанный факт,
   подтверждение, остаток задания и общие показатели работы.
3. Оставьте поле пустым для независимого ручного факта. Выбор наряда сохраняет
   ссылку на его строку; предыдущие события не изменяются. Частичное выполнение
   регистрируется несколькими событиями, без замены накопительной суммы.
4. Если ввод превысит задание строки, откроется предупреждение. На этом шаге
   событие ещё не создано. Для сохранения нужны отдельная отметка согласия и
   причина. При повторном сохранении все проверки выполняются заново под
   блокировкой записи. Превышение задания отличается от превышения плана ведомости;
   прогресс по плану по-прежнему ограничен 100%.
5. В **«Подтверждении»** выберите работу с неподтверждённым фактом, дату, объём и
   документ-основание. Наряд необязателен и доступен, даже если исходный факт
   зарегистрирован без него. Лимит подтверждения — общий накопленный факт работы
   на дату подтверждения за вычетом всех её подтверждений.

Кнопки **«Добавить факт из наряда»** и **«Подтвердить из наряда»** в карточке
открывают те же формы и журналы с заранее выбранной строкой.
В общем журнале источник остаётся `manual`, в том числе при выборе наряда.
При входе непосредственно из карточки источник — `work_order`. Связь с документом
хранится отдельно от источника; старые `legacy` / `manual` не изменяются.
Нельзя подменить источник через произвольное поле формы.

## Общие показатели и связанные события

Карточка и печать явно разделяют показатели. Например:

| Показатель | По работе в целом | Со ссылкой на НЗ-0001 |
| --- | ---: | ---: |
| Факт | 150 м² | 100 м² |
| Подтверждение | 100 м² | 60 м² |
| Ожидает подтверждения | 50 м² | Не является распределением общего остатка |

При задании 120 м² остаток задания — 20 м². Подтверждение со ссылкой на наряд
не устанавливает связь с конкретным событием выполнения. Оно может превышать
связанный факт этого наряда, если общий факт работы достаточен. В таком случае
показано пояснение; исходный факт не перепривязывается к документу.

Выдача, сдача, проверка и закрытие сами по себе не создают событий объёмов.
Снимки в истории решений используются для аудита, расчёт прогресса их не суммирует.

## Статусы и проверка

| Действие | Переход / правило |
| --- | --- |
| Выдать | `draft → issued`, неизменяемый номер и снимки реквизитов |
| Первый положительный факт со ссылкой на строку | `issued → in_progress`, один переход независимо от количества следующих событий |
| Факт без наряда или подтверждение | Статус не меняется |
| Сдать на проверку | `in_progress → submitted`, явное действие, положительный связанный факт обязателен |
| Проверить | `submitted → accepted`, ответственное лицо и отметка каждой строки обязательны |
| Повторить проверку | В `accepted`, новая неизменяемая запись решения без фиктивного перехода статуса |
| Закрыть | `accepted → closed`, отдельное действие; при остатке нужен комментарий |
| Отменить | Из `draft`, `issued`, `in_progress`, обязательное основание; события объёмов сохраняются |

Обычный факт со ссылкой на наряд разрешён в `issued` / `in_progress`, подтверждение —
также в `submitted`. После проверки или закрытия доступны только корректировки
связанных исходных событий. Независимые события работы не меняют документ.
При изменении действующего плана новые события требуют наличия позиции в текущей
утверждённой версии; прежняя версия и строка выданного наряда сохраняются.
Архивный корпус не допускает обычных новых событий, история и корректировки доступны.

Для сдачи, проверки и закрытия выбирается активный сотрудник текущего объекта.
Сохраняются имя на момент действия, UTC-время, комментарий, показатели и история
статуса. Проверяющий отмечает каждую строку и может указать замечания. Эти отметки
не являются подтверждением объёмов или юридически значимой электронной подписью.

Если события изменились после открытия формы, решение отклоняется: обновите
карточку и проверьте суммы заново. Закрытие требует проверки актуальных данных.
Неполное выполнение не мешает закрытию после ввода комментария об остатке.

## Корректировки и история

Уменьшение — отдельное событие со ссылкой `correction_of_id` и комментарием.
Ссылка на строку наряда наследуется от исходного события и не может меняться.
Нельзя приписать старый независимый факт наряду через корректировку.
Суммы по работе и строке проверяются на всех затронутых исторических границах.
Подтверждение в целом не может превышать факт; при необходимости сначала исправьте
подтверждение, затем факт. Нулевая запись и обычный отрицательный ввод запрещены.

Аннулирование всех связанных фактов не откатывает статус автоматически.
Карточка показывает предупреждение. После корректировки проверенных данных прежняя
отметка явно помечается как устаревшая. После закрытия статус и снимок закрытия
сохраняются; текущие уточнённые объёмы показаны отдельно от прежнего решения.
Автоматического переоткрытия документа нет.

В карточке задаются отчётная дата и отсечение знаний. События фильтруются по дате
выполнения/подтверждения и моменту регистрации. Статусы и решения фильтруются по
собственной истории, не позднее конца отчётного дня и отсечения знаний. Печать
сохраняет выбранный срез. До создания документа просмотр недоступен; история
редакций черновика до выдачи не реконструируется, снимок будущей выдачи не выдаётся
за прошлое состояние.

## Печать

Нажмите **«Печатная форма → Печать / Сохранить PDF»**. Используется локальный
HTML/CSS, A4 в альбомной ориентации. Показаны только связанные с нарядом события,
статус, замечания, проверка и ответственные за сдачу/проверку/закрытие. Если событий
нет, ячейка остаётся пустой; при нулевой сумме реальных корректируемых событий
показывается 0. Связанное подтверждение не выдаётся за приёмку несвязанного факта.

На Mac проверьте A4, альбомную ориентацию и браузерные колонтитулы в диалоге печати.
Длинные документы занимают несколько страниц. Новую версию нужно повторно принять
на целевом Mac/Safari; выполненная проверка Chromium/Linux этого не заменяет.

## Обновление существующей установки на Mac

Новых зависимостей нет, `start.command` и офлайн-режим сохранены.

1. Завершите приложение через меню либо `Ctrl+C` в Terminal.
2. Перейдите в свой каталог и создайте проверенную копию через SQLite Backup API:

   ```bash
   cd "/путь/к/construction-progress"
   .venv/bin/python - <<'PY'
   from app.database import connect, backup_database
   db = connect("data/construction_progress.sqlite3")
   try:
       print(backup_database(db, label="manual-stage33"))
   finally:
       db.close()
   PY
   ```

3. Обновите файлы этой версии, сохранив собственные `data` и `.venv`. Для Git-установки
   после публикации версии можно использовать `git pull --ff-only`. Не подменяйте
   собственную базу файлом из чужого архива.
4. Диагностика и запуск:

   ```bash
   ./start.command --check
   ./start.command
   ```

   `--check` не выполняет миграции. Обычный запуск автоматически применяет 007.
   Перед обновлением базы 006 создаётся проверенная копия
   `data/backups/before-work-order-events-*.sqlite3`. Для более ранней схемы копия
   создаётся перед первым ожидающим обновлением. SQL выполняется транзакционно;
   проверяются количества строк, SHA-256 исходных колонок всех пользовательских
   таблиц, `integrity_check` и внешние ключи. При ошибке 007 откатывается вместе
   с DDL и маркером применения; предмиграционная копия сохраняется.
5. Для отдельной приёмки рабочих данных не открывайте:

   ```bash
   ./start.command --test-db
   ```

   В тестовом объекте повторите пример 70 + 30 связанных м² и 50 м² без наряда,
   затем 60 м² подтверждения с нарядом и 40 м² без него. Проверьте 150/100 в целом
   и 100/60 по наряду, сдачу/проверку/закрытие, печать и повторный запуск.

При ошибке сохраните сообщение из Terminal и выполните `./start.command --check`.
Не удаляйте маркеры миграций вручную. Для восстановления остановите сервер,
сохраните ошибочный файл отдельно и верните **копию** своего предмиграционного
файла на путь `data/construction_progress.sqlite3`. Все приложения, открывавшие
базу, должны быть закрыты. Данные после момента резервирования в копии отсутствуют.
Подробнее: [диагностика и восстановление](macos_first_run.md).

# Construction Progress — результаты этапа 3.3

## Реализовано

Необязательная связь событий факта и подтверждения со строкой выданного наряда,
ввод из общего журнала или карточки, независимые общие и связанные суммы,
частичное выполнение/подтверждение, отдельное разрешение превышения задания.
Первый положительный связанный факт запускает наряд; сдача, проверка каждой
строки и закрытие выполняются явно с ответственным и неизменяемой историей.
Неполное задание закрывается с комментарием об остатке.

Существующее ядро `app/calculation_engine` и нормативно-весовая модель не изменены.
Проектирование и СМР рассчитываются раздельно. Наряд не обязателен для регистрации
объёмов. Источник общего ввода остаётся `manual` независимо от выбора наряда;
вход из карточки использует `work_order`. Ссылка на документ отделена от источника.

## SQLite и сохранность

Новая [миграция 007](../migrations/007_work_order_events.sql) добавляет nullable FK
`work_order_line_id` в оба существующих журнала. `work_order_id` определяется через
строку без дублирования. Добавлены причина превышения задания, основание перехода,
неизменяемые решения `work_order_workflow_actions` и отметки `work_order_line_reviews`.
Прежняя `work_order_approvals` сохраняет свои строки выдачи; новые решения расширяют
её механизм без пересоздания ограниченной таблицы 006. [Полная схема](schema.md#аддитивное-расширение-007-события-нарядов-и-решения).

До миграции создаётся проверенная копия SQLite Backup API. DDL, проверки и маркер
выполняются в одной транзакции. До/после сверяются все исходные столбцы и ID всех
пользовательских таблиц, включая персонал, документы, счётчики, журналы и аудит.
Проверяются количества строк, SHA-256, `integrity_check`, внешние ключи.
Повторное применение не дублирует данные. Ошибка SQL и искусственное изменение
старых строк в конце миграции проверены: схема и данные откатываются, копия остаётся.
Тестовый пример 600/450 при плане 1000 сохранил **60% / 45%** до и после 007.
Миграции **001–006 побайтно неизменны**.

Рабочий файл в репозитории не использовался для тестов и не изменялся:

```text
SHA-256: 10f7b9964447ec33eb9d4865ef38b52384f606174217c1304d420510a55dc036
Время изменения: совпало до/после
Проверенная предмиграционная копия: создана через SQLite Backup API
```

Отдельная согласованная копия именно этого файла обновлена до 007. Все значения
его 10 исходных таблиц совпали; повторная инициализация, integrity_check и FK
прошли. Исходный файл содержит миграции 001–004; обычный следующий запуск применит
005–007 с предварительным резервированием. Диагностика `--check` его не обновляет.
База пользователя на Mac не открывалась; при обновлении она получает собственную
локальную резервную копию.

## Приёмка Chromium

Проверка выполнена в Chromium 154 на Linux через реальные формы и `start.command`.
База находилась во временном каталоге с пробелами и кириллицей. Серверу были
запрещены внешние соединения; браузер регистрировал и блокировал внешние запросы.

Объект «Школа», корпус «Учебный», этаж 3, штукатурка стен, план 1000 м²,
учебный пользовательский норматив 0,8 чел.-ч/м², задание НЗ-0001 — 120 м²:

| Проверяемый результат | Значение |
| --- | ---: |
| Факт: 70 + 30 с нарядом, 50 без него | **150 м²** |
| Подтверждение: 60 с нарядом, 40 без него | **100 м²** |
| Ожидает подтверждения в целом | **50 м²** |
| Факт, связанный с НЗ-0001 | **100 м²** |
| Подтверждение, связанное с НЗ-0001 | **60 м²** |
| Остаток задания | **20 м²** |
| Статус после явной сдачи, проверки и закрытия | **closed** |

История: `draft → issued → in_progress → submitted → accepted → closed`.
Второй факт не создаёт повторного перехода. Закрытие сохраняет снимок 100/60/20
и комментарий о переносе 20 м² на следующую смену. Выдача/сдача/проверка/закрытие
не создают фактические или подтверждающие события.

Дополнительный НЗ-0002 по той же работе: новый факт введён без наряда, затем 10 м²
подтверждены с его выбором. Проверены **0 м² связанного факта / 10 м² связанного
подтверждения**, статус **issued**, прежний факт остался без ссылки. Пояснение
не приписывает наряду выполнение независимого факта.

## Обновление и ограничения

Остановите сервер, создайте копию своей базы, обновите файлы без замены `data`
и `.venv`, затем выполните `./start.command --check` и `./start.command`.
Пошаговые команды резервирования, запуска, приёмки и восстановления приведены в
[инструкции обновления на Mac](work_order_events.md#обновление-существующей-установки-на-mac).

Предыдущий этап 3.2 принят пользователем на macOS. Эта версия проверена в
Linux/Chromium; **новые изменения требуют повторной приёмки на Mac/Safari**.
Поддерживаемые Python, SQLite, зависимости и запуск не менялись; новой проверки
на реальных Catalina Intel или современных Intel/Apple Silicon в этой среде нет.

Приложение остаётся локальным однопользовательским. Выбранное ответственное лицо
не является аутентификацией или юридически значимой подписью. Нет резервирования
остатка между заданиями, пагинации больших журналов, реконструкции редакций
черновика и автоматического переоткрытия закрытого документа. Корректировки после
закрытия сохраняют решение и предупреждение; решение не выдаётся за проверку
изменившихся данных. Прямой SQL не является поддерживаемым API межстрочных проверок.
Следующий этап, упаковка .app и новые бизнес-модули не начинались.

# Первый запуск на macOS — приёмка этапа 3

Приложение подготовлено к испытаниям из исходников. **На реальных Mac оно пока не
проверялось.** Ни проверки Linux, ни моделирование архитектур не подтверждают
совместимость с Catalina, современными macOS или Safari.

Целевые устройства: Catalina 10.15 Intel, macOS 13+ Intel, macOS 13+ Apple Silicon.
Остаётся выбранная связка CPython 3.13.12 / стандартная GIL-сборка; версии библиотек
зафиксированы в `requirements/macos_catalina.txt` и `requirements/web.txt`.
Документальные основания: [compatibility.md](compatibility.md).

## 1. Подготовка компьютера и каталога

1. Установите официальный [CPython 3.13.12 universal2](https://www.python.org/downloads/release/python-31312/).
   Не используйте системный Python macOS. Само приложение допускает CPython 3.13.x;
   для воспроизводимой приёмки рекомендуется 3.13.12. Экспериментальная free-threaded
   сборка для этой приёмки не используется.
2. Перенесите исходники в свой доступный для записи каталог. Не переносите `.venv`
   с Linux, другого Mac или другой архитектуры. Рабочие данные находятся отдельно
   в `data/construction_progress.sqlite3`.
3. Откройте Terminal. Перейдите в каталог проекта. Например, если он в Downloads:

```bash
cd "$HOME/Downloads/construction-progress"
```

Если каталог другой, напечатайте `cd `, перетащите папку проекта в Terminal и
нажмите Enter. Кавычки сохраняют пути с пробелами и кириллицей.

```bash
pwd
chmod +x start.command
/bin/bash --version
/usr/bin/sw_vers -productVersion
/usr/bin/uname -m
```

Скрипт использует `/bin/bash`, а не настройки интерактивной оболочки zsh.
В нём нет Bash 4+ конструкций, пустых массивов под `set -u`, GNU `readlink -f`
или GNU `realpath`. Фактический запуск на Apple Bash 3.2 должен быть проверен здесь.

## 2. Диагностика до установки

```bash
./start.command --check --test-db
```

Режим не запускает сервер/браузер, не создаёт `.venv`, базу и каталоги базы,
не применяет миграции, не заполняет справочники, не устанавливает пакеты и не
обращается в интернет. Существующая выбранная база открывается только для чтения.
Для диагностики записей байткода также используется Python `-B`.

До подготовки отсутствие окружения или библиотек ожидаемо даст ненулевой код.
Если Python не найден, установите его или задайте полный путь:

```bash
CP_PYTHON="/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13" ./start.command --check --test-db
```

Отчёт показывает версию macOS, архитектуру оборудования и Python, Rosetta,
интерпретатор и окружение, SQLite именно этого интерпретатора, точные версии
зависимостей и возможность их импорта, путь/целостность базы, состояние миграций
и доступность привязки к `127.0.0.1`.

На Catalina отсутствующие `sysctl`-ключи Apple Silicon допустимы: Catalina
Intel-only и предшествует Rosetta 2. На новых macOS при недоступных сведениях
аппаратная архитектура помечается как неопределённая, а не угадывается.
При `x86_64` Python на Apple Silicon отчёт предупреждает о Rosetta. Для нативной
приёмки Apple Silicon нужен `arm64` Python и соответствующие бинарные зависимости.

## 3. Первоначальная подготовка — явное действие с интернетом

```bash
./start.command --prepare --test-db
```

Только флаг `--prepare` разрешает сетевую установку зафиксированных зависимостей.
Команда создаст окружение при его отсутствии, установит готовые колёса, проверит
импорты и запустит приложение с отдельной базой приёмки. Пакеты не собираются
компилятором на Mac. `--prepare` нельзя совмещать с `--check`.

Браузер откроет адрес вида `http://127.0.0.1:54321`. Порт назначается ОС;
он может быть другим. Если браузер не открылся, скопируйте локальный адрес из
Terminal. Тестовый режим явно отмечен сообщением «РЕЖИМ ПРИЁМКИ» в Terminal.

**Приёмочная база:** `data/acceptance/acceptance.sqlite3`.
Она создаётся без этажей, учётных позиций и придуманных нормативов; в ней только
исходные три корпуса и 15 кодов. Введённые при приёмке данные сохраняются.
Рабочая база не открывается. Совмещение `--test-db` и `--db` запрещено;
символическая или жёсткая ссылка тестового файла на рабочий также отклоняется.

## 4. Завершение и повторная проверка

Нажмите «Завершить работу» в боковом меню или Ctrl+C в Terminal. После сообщения
«Сервер остановлен. Данные сохранены» выполните:

```bash
./start.command --check --test-db
.venv/bin/python -m pytest -q
```

Для приложения необходимы веб-зависимости; полная диагностика проверяет также
инструменты тестов. `--check` возвращает 0 при успехе, 1 при выявленных проблемах,
2 при неверных параметрах. В среде, запрещающей даже локальные сокеты, проверка
порта закономерно завершается ошибкой; это не потребность приложения в интернете.

Оставьте отчёт для приёмки:

```bash
./start.command --check --test-db > "$HOME/Desktop/construction-progress-check.txt" 2>&1
```

Закрытие вкладки не останавливает сервер. Поддерживаются SIGINT, SIGTERM и SIGHUP
при закрытии Terminal; рекомендуемый способ — кнопка приложения или Ctrl+C.

## 5. Обычный офлайн-запуск и приёмочный сценарий

Отключите Wi-Fi и Ethernet **после** подготовки зависимостей. Запустите снова:

```bash
./start.command --test-db
```

Проведите [чек-лист приёмки](macos_acceptance_checklist.md). Тестовые входные данные:
план 1000 м², учебная норма 0,8 чел.-ч/м², факт 600 м², подтверждено 450 м².
Ожидается 60% и 45%, плановая трудоёмкость 800 чел.-ч, остаток 400 м² / 320 чел.-ч.
Норма служит только тестовым вводом, не справочником строительных нормативов.

Приложение не запускает pip без `--prepare`. Браузер, страницы, CSS, JS и расчёты
работают локально. Возможные сетевые функции самого браузера вне приложения
не являются необходимой частью Construction Progress.

Для запуска без автоматического открытия браузера:

```bash
./start.command --test-db --no-browser
```

Когда испытания закончены и нужен обычный рабочий запуск:

```bash
./start.command
```

Он открывает `data/construction_progress.sqlite3`, при необходимости применяя
существующие миграции. **Рабочий запуск не переносит в неё тестовые данные.**
Для диагностики рабочей базы без её изменения:

```bash
./start.command --check
```

## 6. Занятый порт

Обычный режим `--port 0` поручает ОС атомарно выбрать свободный порт; отдельного
окна между поиском порта и запуском сервера нет. В диагностике проверочный сокет
закрывается сразу, поэтому доступность фиксированного порта проверяется только
на этот момент и не резервируется для будущего запуска.

```bash
./start.command --check --test-db --port 5100
./start.command --test-db --port 5100
```

Если порт занят, не завершайте чужие программы вслепую. Используйте:

```bash
./start.command --test-db --port 0
```

Либо другой проверенный порт. Ошибка запуска занятого порта возвращает код 2
и русское сообщение без traceback; ранее запущенный процесс не завершается.

## 7. Восстановление окружения

При сообщениях о несовместимом Python, повреждённом `.venv`, неправильной
архитектуре MarkupSafe или ошибке импорта сначала завершите приложение.
Окружение можно сохранить и создать заново, не затрагивая каталог `data`:

```bash
if [ -d .venv ] || [ -L .venv ]; then
    mv .venv ".venv.before-repair-$(date +%Y%m%d-%H%M%S)"
fi
CP_PYTHON="/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13" ./start.command --prepare --test-db
```

После остановки вновь запущенного приложения:

```bash
./start.command --check --test-db
.venv/bin/python -m pytest -q
```

На Apple Silicon для **нативного** окружения, после сохранения старой `.venv`:

```bash
CP_PYTHON="/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13" /usr/bin/arch -arm64 /bin/bash ./start.command --prepare --test-db
```

Официальный интерпретатор должен быть universal2. После остановки приложения
проверьте `./start.command --check --test-db`: оборудование и Python должны быть
`arm64`, Rosetta — «нет». Не смешивайте x86_64 и arm64 колёса в одном окружении.

При ошибках SSL первоначальной установки проверьте часы системы и выполните
официальную команду установки сертификатов Python **вручную с интернетом**:

```bash
"/Applications/Python 3.13/Install Certificates.command"
./start.command --prepare --test-db
```

Не отключайте проверку TLS. Если интернета на целевом Mac нет, перенесите готовый
wheelhouse под выбранную версию Python и архитектуру. Например, для подготовки
wheelhouse на другом совместимом Mac той же архитектуры:

```bash
python3.13 -m pip download --only-binary=:all: -r requirements/macos_catalina.txt -d wheelhouse
```

На целевом Mac из каталога проекта:

```bash
/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13 -m venv .venv
.venv/bin/python -m pip install --no-index --find-links ./wheelhouse -r requirements/macos_catalina.txt
./start.command --check --test-db
./start.command --test-db
```

Здесь `.venv` должна отсутствовать или быть предварительно сохранена под другим
именем. Не устанавливайте arm64 wheelhouse на Intel и наоборот.

## 8. Ошибки доступа и базы данных

- `Permission denied` для скрипта: `chmod +x start.command`; также можно явно
  выполнить `/bin/bash ./start.command --check --test-db`.
- Недоступен каталог базы: разместите проект и данные в своём доступном для записи
  каталоге. Не запускайте приложение через `sudo`. При переносе между компьютерами
  не копируйте `.venv`.
- База занята: остановите второй экземпляр кнопкой/Ctrl+C, затем повторите
  `./start.command --check`. Автоматическое удаление журналов SQLite не выполняется.
- Повреждён файл или нарушены связи: остановите приложение и сохраните **весь**
  каталог `data`, включая возможные `-journal`, `-wal`, `-shm`. Не удаляйте их
  вручную и не заменяйте рабочую базу пустым файлом.

Команда сохранения исходных файлов после остановки приложения:

```bash
cp -Rp data "$HOME/Desktop/Construction Progress data backup $(date +%Y%m%d-%H%M%S)"
```

Для продолжения испытаний используйте `./start.command --test-db`; рабочий файл
не будет открыт. Восстановление повреждённой рабочей базы выполняется отдельно
из проверенной резервной копии, с сохранением исходной версии. `--check` не чинит
и не перезаписывает данные.

Если требуется начать **тестовую** приёмку заново, сначала остановите её сервер
и сохраните только отдельный тестовый каталог:

```bash
mv data/acceptance "data/acceptance.before-repair-$(date +%Y%m%d-%H%M%S)"
./start.command --test-db
```

Не перемещайте и не удаляйте рабочий `data/construction_progress.sqlite3` для
сброса тестовой приёмки.

Упаковка `.app`, экспорт и Windows-версия в этот этап не входят.


## Обновление до объектов (3.1)

Для уже установленного приложения используйте [инструкцию рабочих пространств](workspaces.md):
она описывает обновление с сохранением `data`/`.venv`, автоматическую проверенную
резервную копию перед 004 и откат. Новых зависимостей нет; обычный запуск остаётся
офлайн. Новая миграция выполняется только при запуске приложения, не в `--check`.

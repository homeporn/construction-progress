# Приёмочные испытания на реальном Mac

**Статус: на реальных Mac не выполнено.** Для каждого устройства заполните
отдельную копию этого листа. Инструкция: [macos_first_run.md](macos_first_run.md).
Выполняйте сценарий только с `--test-db`, не на рабочей базе.

Целевая матрица:

- [ ] Catalina 10.15 Intel x86_64.
- [ ] macOS 13+ Intel x86_64.
- [ ] macOS 13+ Apple Silicon arm64, нативный Python, Rosetta «нет».

Если Rosetta используется намеренно, фиксируйте её отдельной конфигурацией,
не засчитывайте как нативную приёмку arm64.

## Запуск и изоляция

- [ ] Исходники помещены в каталог с пробелами и кириллицей. Перенесённая `.venv`
      другого компьютера не используется.
- [ ] `./start.command --check --test-db` до подготовки не создал окружение и базу;
      отсутствие зависимостей отмечено понятными сообщениями.
- [ ] Явно выполнено `./start.command --prepare --test-db`; зависимости установлены
      без ручной компиляции. Браузер открыл `http://127.0.0.1:<порт>`.
- [ ] В Terminal виден «РЕЖИМ ПРИЁМКИ», путь заканчивается на
      `data/acceptance/acceptance.sqlite3`.
- [ ] Рабочая база не создана и не изменена; если она уже есть, её контрольная
      сумма до/после диагностики и приёмки одинакова.
- [ ] Начальные данные: три корпуса и 15 кодов; этажи и нормы не появились сами.
- [ ] Все семь разделов открываются в Safari. Корпуса А/B/C и СМР/проектирование
      показаны отдельно. Без плана отображается «Нет данных».

## Рабочий сценарий на тестовых данных

- [ ] В корпусе А созданы этажи `-1`, `1`, `Тех` с независимым порядком.
      Корпуса B/C не получили эти этажи автоматически.
- [ ] Для этажа `1` добавлена позиция `ОТД.СТ.01 — штукатурка`, единица `м²`, СМР.
- [ ] Создан черновик, введены план `1000` и учебная норма `0,8`, нажато «Сохранить».
      Плановая трудоёмкость равна `800` чел.-ч. Норма не была подставлена автоматически.
- [ ] Версия утверждена; план и норма недоступны для изменения в ней.
- [ ] Внесён факт `600` м² сегодняшней датой. Журнал показывает отдельные дату
      выполнения и момент регистрации UTC.
- [ ] Подтверждено `450` м² с документом «Тестовый акт №1» и комментарием.
      Подтверждение появилось в отдельном журнале.
- [ ] Дополнительное подтверждение `151` м² отклонено: накопление превысило бы 600.
      Исходные `450` м² и журнал не изменились после ошибки.
- [ ] Сводка / ведомость / история показывают `60%` факта, `45%` подтверждения.
      Проектирование и корпуса без плана показывают «Нет данных».
- [ ] В истории на сегодня указана правильная версия плана, `800` чел.-ч плана,
      `400` м² и `320` чел.-ч остатка по факту.
- [ ] Выбран момент знаний после утверждения плана, но до регистрации факта:
      факт отсутствует. Момент после регистрации возвращает 60% / 45%.
      Если момент предшествует утверждению, версия корректно помечается недоступной.
- [ ] Фильтры корпуса, этажа, элемента, вида работ и версии работают, проценты
      рассчитываются сервером и не объединяют направления.

## Повторный запуск, порт и офлайн-работа

- [ ] Сервер завершён кнопкой, Terminal сообщил о сохранении данных.
- [ ] `./start.command --test-db` повторно показывает те же позиции, версию и
      события; корпуса и коды не продублированы.
- [ ] Приложение штатно завершено Ctrl+C. Порт освобождён.
- [ ] Проверен SIGHUP при закрытии Terminal; после нового запуска данные сохранились.
- [ ] Диагностика существующей тестовой базы: quick_check `ok`, нарушений FK 0.
- [ ] В первом Terminal сервер запущен с `--test-db --port 5100`. Во втором
      `--check --test-db --port 5100` сообщает, что порт занят; запуск с `--port 0`
      выбирает свободный порт и не останавливает первый сервер.
- [ ] После первоначальной установки отключены Wi-Fi и Ethernet; выполнен новый
      запуск с `--test-db`, открыты все разделы, получен исторический отчёт.
      Нет требований скачать пакеты, CDN или внешние ресурсы.
- [ ] `.venv/bin/python -m pytest -q` проходит без интернета.
- [ ] После остановки `./start.command --check --test-db` проверяет данные без
      изменения SQLite и без миграций. Лог сохранён.

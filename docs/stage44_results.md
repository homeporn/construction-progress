В существующий проект добавлен локальный модуль управленческих начислений.
Почасовая, окладная, сдельная и комбинированная системы интегрированы с
утверждёнными табелями и независимым подтверждением объёмов. Изменения не
публиковались в GitHub, Railway или другом внешнем сервисе.

Функциональные серверные сценарии проверены. Реальная браузерная приёмка
остаётся незавершённой: Chromium в данной среде падает до создания страницы.
Это ограничение не скрывается успешными Flask-проверками.

## Браузер и воспроизведение

Протокол: [browser_results.json](stage44/browser_results.json).
Инструмент: `tests/browser_stage44.py`.

Одна реальная попытка запуска `/usr/bin/chromium` через Playwright с размером
1366×768 завершилась в crashpad: `setsockopt: Operation not permitted`, SIGTRAP.
Страница не создана. Скриншотов нет. JavaScript-ошибки, внешние запросы и
поведение браузера **не наблюдались**, а не «отсутствовали». В JSON эти поля
оставлены `null`. Реальные Safari, Edge, Windows этим этапом не проверялись.

Отдельный backend-приёмочный прогон через реальные Flask test_client и
отрисованные CSRF-формы прошёл: разделы, условия/ставки, явный сдельный просмотр
и подтверждение, премия, все шесть числовых сценариев, утверждение, старая и
новая версии, восемь листов Excel и числовое совпадение компонентов с итогом.
Без CSRF и с чужим Origin получен ожидаемый403. Первичные данные до/после
совпали; integrity/FK checks прошли. Это не проверяет реальный TCP/WSGI транспорт.

```bash
.venv/bin/python -m pytest -q
```

На машине с Playwright и работающим Chromium:

```bash
python tests/browser_stage44.py
```

Обычный запуск создаёт новую временную синтетическую базу и обновляет протокол.
Для повторения только серверной приёмки с сохранением прежнего свидетельства
падения Chromium:

```bash
python tests/browser_stage44.py --refresh-backend
```

При сохранённом браузерном блокере ожидаемый код выхода этой последней команды2,
даже если поле `backend_acceptance.status` равно `passed`.

## Обновление на macOS

1. Завершите Construction Progress и его локальный сервер. Сохраните каталог
   проекта, свою базу, экспорты и резервные копии в защищённом месте.
2. Перед заменой кода создайте согласованную SQLite-копию через Backup API.
   Пример для стандартного пути из корня проекта (Python существующей установки):

```bash
.venv/bin/python - <<'PY'
from pathlib import Path
from app.database import connect, backup_database
path = Path('data/construction_progress.sqlite3')
assert path.is_file(), 'Укажите фактический путь существующей базы'
db = connect(path)
try:
    print(backup_database(db, label='manual-stage44'))
finally:
    db.close()
PY
```

3. Обновите программные файлы, сохраняя свою `data/`, `.venv`, `backups/`,
   `exports/`, `logs/`. Не заменяйте свою базу демонстрационной и не удаляйте
   старые миграции. Новых Python-зависимостей этап4.4 не требует.
4. Выполните `./start.command --check`, затем проверьте на отдельной базе
   `./start.command --test-db`. После этого запустите `./start.command`.
   Перед необходимым обновлением штатный migrate создаёт копию; для011→012
   она имеет имя `data/backups/before-payroll-*.sqlite3`.
5. Если нужна явная миграция, укажите свой реальный путь:

```bash
.venv/bin/python -m scripts.init_db --db data/construction_progress.sqlite3
.venv/bin/python - <<'PY'
from app.database import connect
db = connect('data/construction_progress.sqlite3')
try:
    assert db.execute('PRAGMA integrity_check').fetchone()[0] == 'ok'
    assert not db.execute('PRAGMA foreign_key_check').fetchall()
    print([r[0] for r in db.execute('SELECT name FROM schema_migrations ORDER BY name')])
finally:
    db.close()
PY
```

6. При ошибке миграции не продолжайте работу с ошибочной установкой.012
   откатывается автоматически; сохраните проверенную копию и сообщение об ошибке.
   Для возврата версии программы используйте соответствующую ей остановленную
   базу из копии, а не пытайтесь вручную удалять таблицы или маркеры.

### Ручная приёмка Mac/Safari

Используйте отдельную синтетическую базу, экран1366×768 и узкое окно.

1. Выберите объект; откройте «Начисления». Проверьте меню, заголовок, фильтры,
   отсутствие зарплатных сумм на общей главной странице.
2. Создайте работника и утверждённый табель. Задайте почасовую ставку350,
   рассчитайте160 часов; проверьте56 000. Проверьте два интервала350/400 и60 000.
3. Повторите оклад80 000 с явной нормой160 и120 часами:60 000. Включите20%
   от базы в комбинированной системе:72 000. Уберите норму и проверьте ошибку.
4. Зарегистрируйте факт и подтверждение без наряда. Явно назначьте исполнителя,
   задайте расценку300, распределите100 единиц поровну пяти работникам;
   предварительно и после подтверждения проверьте30 000 и по6 000.
5. Повторите КТУ, ручные суммы и распределённые часы4.3. Проверьте ошибку
   превышения остатка, чужого работника и повторной оплаты источника в другом
   месяце. Измените ставку после просмотра: старое подтверждение отклоняется.
6. Добавьте ручную премию с причиной; передайте расчёт на проверку, утвердите,
   закройте. Проверьте запрет редактирования и неизменность старого Excel.
7. Создайте и утвердите корректировку табеля, затем корректирующую версию
   начислений. Проверьте предупреждение, разницу и выбор старой версии.
8. Экспортируйте XLSX, откройте восемь листов в Excel/Numbers. Проверьте суммы,
   денежный формат, даты, валюты, снимок источников. Пользовательский текст
   вида `=1+1` должен оставаться текстом, а не формулой.
9. Переключите объект/архив, перезапустите приложение, отключите интернет.
   Проверьте сохранность данных, отсутствиеHTTP500, JS-ошибок и внешних запросов
   в инструментах Safari. Зафиксируйте версию macOS/Safari и скриншоты.

## Известные ограничения

Нет налогов, бухгалтерской отчётности, отпускных/пособий, платёжных документов,
фиктивных пользователей или юридической подписи. Расчёты не являются выплатами.
Данные чувствительные: права ОС, шифрование диска, защита копий и экспортов
остаются ответственностью владельца локальной установки до этапа4.6.

Автоматическая премия за выработку требует полной персональной атрибуции.
Неподтверждённый объём для автоматической сдельной оплаты не используется.
Интерфейс ограничивает одну сдельную операцию50 получателями; источник можно
разделить на несколько частей. Валюты RUB/USD/EUR, два знака; конвертации нет.
Общая эффективность по работам доступна лишь для надёжно связанных сдельных
начислений, а не предположительного распределения всего фонда.

Реальная браузерная приёмка и пользовательская проверка macOS остаются
обязательными перед эксплуатацией с реальными расчётными данными. Windows Build
Kit и частичная нагрузочная работа4.2.1 сохранены без изменения статуса.
Этапы4.5/4.6, сетевое планирование, зарплатные выплаты и облачная публикация
не реализовывались. Push не выполнялся.

# Совместимость и проверенные версии

Дата проверки источников: 2026-10-16. Хост разработки — Linux x86_64.
Документальная совместимость и фактические испытания указаны отдельно.

## Выбор до разработки

Расчётное ядро использует `sqlite3`, `decimal`, `datetime`, `pathlib`, `dataclasses`,
`argparse`, `json`, `enum`, `importlib.metadata` из стандартной библиотеки.
У расчётного ядра сторонних runtime-зависимостей нет. Зависимости веб-интерфейса
этапа 2 приведены ниже. `pip` и `venv` предоставляются официальным
интерпретатором; их обновление из сети не выполняется. Зависимости `exceptiongroup`
и `tomli` у pytest условны для Python <3.11 и в выбранной связке не нужны.

Выбор pure-Python wheel устраняет необходимость macOS ABI-совместимых сторонних
бинарных пакетов. Это **вывод из метаданных**, а не доказательство запуска на Catalina.
Минимальная версия macOS официального интерпретатора проверена отдельно; нельзя
переносить этот вывод на произвольные Homebrew/Conda-сборки или Python 3.14+.

## Фактические испытания

| Среда | Результат |
| --- | --- |
| Linux x86_64, CPython 3.13.5, SQLite 3.46.1 | pytest и локальный запуск выполнены; итоговый результат записан ниже |
| macOS Catalina 10.15 Intel, Python.org CPython 3.13.12 / SQLite 3.50.4 | Требуется отдельная проверка на целевой системе |
| macOS 13+ Intel/Apple Silicon | Требуется отдельная проверка |
| Windows 10/11 | Требуется отдельная проверка |

Установлены именно зафиксированные версии pytest, iniconfig, packaging, pluggy и
Pygments из таблицы. Linux-интерпретатор 3.13.5 предоставлен средой разработки;
это не установщик Python.org для macOS и не заявленная проверка версии 3.13.12.
Обычный скрипт допускает 3.13.x, но при подготовке Catalina рекомендуется
воспроизводимая выбранная версия 3.13.12. После обновления интерпретатора или
зависимостей следует заново пройти целевые испытания.

Прогон первого этапа (2026-10-16):

```text
$ .venv/bin/python -m pytest -q
94 passed in 0.58s
```

Также выполнены `compileall`, `bash -n start.command`, проверка зафиксированных
версий через `scripts.check_environment --tests`, демонстрация 60%/45%, повторное
открытие рабочей базы и запуск скрипта из `/tmp`. Путь к базе с пробелами и кириллицей
проверен. Запуски без `--prepare` выполнены в песочнице без сетевых разрешений.

## Приёмка на Catalina Intel (с учётом этапа 2)

1. Установить официальный universal2 CPython 3.13.12, выбрать обычную сборку с GIL.
2. Перенести исходники в каталог с пробелами и кириллицей в имени.
3. Выполнить `./start.command --prepare` по явной команде пользователя с интернетом.
4. Выполнить `.venv/bin/python -m scripts.check_environment --tests`;
   зафиксировать `sw_vers`, архитектуру, версию Python и `sqlite3.sqlite_version`.
5. Выполнить `.venv/bin/python -m pytest -q` и сохранить результат.
6. Выполнить `./start.command` дважды; проверить три корпуса, 15 кодов и отсутствие дублей.
7. Выполнить сценарий веб-интерфейса: этаж → позиция → черновик → план/норма →
   утверждение → факт 600 → подтверждение 450 на плане 1000. Проверить 60% / 45%.
   `./start.command --demo` остаётся отдельной консольной проверкой в памяти.
8. Отключить сеть, повторить обычный запуск, демонстрацию и тесты.
9. Проверить запуск двойным щелчком Finder и из Terminal из другого каталога,
   автоматическое открытие Safari и работу на 127.0.0.1. Завершить кнопкой, затем
   Ctrl+C, повторно открыть приложение и убедиться в сохранности данных.
10. На копии базы проверить `PRAGMA integrity_check` и `PRAGMA foreign_key_check`,
    сохранность исходных Decimal-строк после миграции и повторных запусков.
11. Повторить приёмку на macOS 13+ Intel и Apple Silicon. Испытания Windows — отдельный будущий этап.

До выполнения этого списка этап не считается испытанным на Catalina.

## Зависимости веб-интерфейса этапа 2

До установки проверены метаданные PyPI, требования Python и файлы колёс.
Выбранные версии зафиксированы в `requirements/web.txt` и включены в полное
окружение через `requirements/macos_catalina.txt`. Версия Python первого этапа сохранена.

| Компонент | Версия | Requires-Python | Колесо / платформа |
| --- | --- | --- | --- |
| Flask | 3.1.3 | >=3.9 | py3-none-any |
| Werkzeug | 3.1.9 | >=3.9 | py3-none-any |
| Jinja2 | 3.1.6 | >=3.7 | py3-none-any |
| MarkupSafe | 3.0.4 | >=3.9 | cp313-cp313-macosx_10_13_x86_64; cp313-cp313-macosx_11_0_arm64 |
| itsdangerous | 2.2.0 | >=3.8 | py3-none-any |
| click | 8.1.8 | >=3.7 | py3-none-any |
| blinker | 1.9.0 | >=3.9 | py3-none-any |

MarkupSafe содержит нативное расширение. Для обычной GIL-сборки CPython 3.13
доступны `markupsafe-3.0.4-cp313-cp313-macosx_10_13_x86_64.whl` и
`markupsafe-3.0.4-cp313-cp313-macosx_11_0_arm64.whl`. Тег первого включает Catalina
Intel; тег второго подходит macOS 13+ Apple Silicon. Остальные зависимости —
чистый Python. `--prepare` использует `--only-binary=:all:`, поэтому не пытается
собирать неподходящую зависимость компилятором на пользовательском Mac.

Это документальная проверка требований и платформенных тегов. Она не заменяет
запуск на целевой ОС и проверку конкретной версии Safari. Рекомендуется актуальная
для Catalina версия Safari, установленная заранее; приложение не требует сетевых
обращений браузера или обновлений во время эксплуатации.

## Подготовка к приёмке — этап 3, 2026-10-17

Версии Python и зависимостей не изменены. Новых библиотек и миграций не добавлено.
Существующие 142 теста сохранены; вместе с новыми сценариями проходят 174 теста.
Целевые архитектуры, Catalina без новых sysctl-ключей, arm64 и Rosetta проверены
unit-тестами с моделированием ответов ОС — **не на реальном Mac**.

В `start.command` оставлены конструкции, совместимые с Bash 3.2; убраны пустые
массивы аргументов под `set -u` и зависимости от GNU-расширений утилит путей.
Фактическая оболочка испытаний — GNU Bash 5.2.37 на Linux. Apple Bash 3.2,
Catalina и современные macOS требуют отдельного выполнения чек-листа.

Добавлены `--check` (без изменения БД/окружения, без сети) и `--test-db` (отдельная
сохраняемая база приёмки). Диагностика проверяет реальный импорт бинарного MarkupSafe,
показывает архитектуру процесса/оборудования и возможную Rosetta. SQLite проверяется
в режиме `mode=ro`; ожидающие миграции только перечисляются. Проверка порта использует
локальную привязку и закрывает сокет, не обещая резервирования порта.

Временная копия проекта с пробелами и кириллицей прошла полный запуск с отдельной
базой и перезапуски. При заблокированных внешних TCP-соединениях Python получены
60% / 45%; рабочий SQLite-файл не изменился. Занятый порт диагностирован по-русски,
SIGINT/SIGTERM/SIGHUP завершили сервер с кодом 0 и освободили сокет.

# Результаты этапа 3.1.1

Дата: 17 октября 2026. Репозиторий `/workspace/construction-progress`.
Среда проверки: Linux x86_64, CPython 3.13.5, SQLite 3.46.1, Chromium.
Пользователь сообщил об успешной проверке версии 3.1 на macOS Monterey в Safari.
Для новых изменений необходима повторная приёмка на Mac; проверки Catalina/Apple
Silicon этим отчётом не заявляются. Новых зависимостей нет.

## Тестирование

До изменений: `228 passed in 7.42s`.
После реализации: `260 passed in 8.71s`, добавлены 32 проверки, прежние тесты сохранены.

Проверены утверждённый/черновой план, отсутствие и появление факта, дельты +200/+400,
частичное/полное подтверждение, новое выполнение после приёмки, уникальность событий,
нулевые/отрицательные обычные объёмы, предел подтверждения именно на дату,
исторические даты/время знаний, корректировки, полностью принятая/нулевая история,
план V1/V2, разные объекты, фильтры, точность при малом Decimal context,
источник события и подмена его из формы, устаревшая форма плана.
Два независимых SQLite-соединения в потоках видят факт 600 и одновременно пытаются
подтвердить по 400: одна операция проходит, другая отклоняется, остаётся 200.

Для миграции 005 проверены исходные ID, даты, объёмы, аудит, 60%/45% до/после,
копия через Backup API, идемпотентность и полный откат при SQL-ошибке с сохранением
копии. Проверки `git diff --check`, синтаксиса JavaScript, Bash и зафиксированных
зависимостей без сети также прошли. Миграции 001–004, `start.command`, requirements,
Decimal-арифметика и файлы формул labor/progress/aggregation не изменены.

## Браузер

Во временной базе через интерфейс созданы «Школа», «Учебный», этаж 3 и позиция
штукатурки стен. Пользовательский учебный ввод: план 1000 м² и норма 0.8 чел.-ч/м²
(не норматив из справочника). До утверждения работа отсутствует в выполнении,
после утверждения появляется. Факт 600 автоматически создаёт строку ожидающих.
Подтверждение 450 оставляет 150, сводка показывает 60% и 45%.

Далее подтверждения 100 и 50 дают 50 и 0. Работа исчезает из ожидающих, остаётся
во «Всех работах». Новый факт 100 возвращает её в ожидающие. Раннее отсечение
знаний по-прежнему показывает остаток 150 и скрывает поздние документы. Проверены
переключение объектов, отключение форм исторического просмотра и защищённое
завершение сервера. Ошибок JavaScript — 0, внешних запросов браузера — 0,
попыток внешних соединений сервера — 0 (внешние сокеты были заблокированы).
Проверены экраны 1440×900 и 1366×768. Рабочая база во время приёмки не открывалась
для записи; сервер запускался через существующий `start.command --db <временный путь>`.

## Сохранность и обновление

Рабочая `data/construction_progress.sqlite3` не изменялась: SHA-256, mtime и список
применённых миграций совпали с началом этапа. `integrity_check=ok`, нарушений FK — 0.
005 применялась только на временных базах. При первом обычном запуске новой версии
на существующей установке создаётся проверенная копия `before-event-flow-*.sqlite3`,
затем в транзакции добавляются только источник и аудит источника в существующих
журналах. Пересоздания базы, копирования учётных позиций или изменения формул нет.
Источник прежних событий — legacy (ранее не фиксировался), новых веб-событий — manual.

Исторический калькулятор теперь использует тот же запрос точных сумм журналов,
что и транзакционная проверка подтверждения. Это перенос запроса в общий метод,
а не изменение математической модели.

Инструкция обновления Mac, сценарии и ограничения: [event_flow.md](event_flow.md).
Исторические/фиксированные срезы и прежние версии — просмотр; новые обычные события
регистрируются из действующего плана, в том числе задней бизнес-датой с текущим
временем регистрации. Очередь ограничена выбранным планом. Большие журналы по-прежнему
требуют профилирования и пагинации. Наряды этапа 3.2 не реализованы.

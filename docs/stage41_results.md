# Этап 4.1 — результаты реализации

Реализованы персонал, постоянные бригады и пятишаговый импорт Excel в существующем
Flask/Jinja2-приложении. Расчётное ядро и журналы факта/подтверждения не изменены.
Разработка завершена без push; публикация выполняется по отдельному запросу пользователя.
Табель, производительность, зарплата и этап 4.2
не реализовывались.

## Исходное состояние и проверки

Дата: 2026-10-20. Среда: Linux x86_64, CPython 3.13.5, SQLite 3.46.1.
Начальный HEAD: `90aa672`. Перед изменениями изучены схема, миграции 001–008,
репозитории персонала/нарядов, выдача, снимки состава и существующие тесты.

Первый запуск исходного набора: **502 passed, 2 failed**. Оба сбоя были
датозависимыми: новые действия аналитических групп получали 20 октября,
а проверки текущего состояния использовали отсечение 19 октября. В этих
проверках отсечение текущего состояния заменено текущим моментом; отдельные
исторические проверки сохранены. Повторный исходный прогон: **504 passed in 36.33s**.

Итоговый полный прогон после реализации:

```text
$ .venv/bin/python -m pytest -q
593 passed in 68.19s (0:01:08)
```

Добавлено **89 сценариев pytest с учётом параметризации**. Старые тесты сохранены;
имитатор HTTP-сервера расширен проверкой нового обработчика, который скрывает
поисковые параметры из технических логов. Все базы тестов временные.

Проверены ручные карточки, обязательные реквизиты, архив/восстановление, одинаковые
ФИО, строки `1`/`01`, переводы и отсутствие пересечений, история с отсечением знаний,
изоляция объектов/подрядчиков и один канонический ID на нескольких объектах.

Импорт: 100 работников, пустые/неверные поля, порядок и отсутствие колонок,
главный лист, неизвестные справочники, повторные строки и два одноимённых человека,
явные сопоставления, сохранённые связи с конфликтом/без него, отсутствие записей
в справочники при просмотре/отмене, пустая бригада без неявного исключения,
параллельные подтверждения, устаревшие данные и полный откат при искусственном сбое.

Безопасность: CSRF/Origin, подмена объекта, формулы с сохранённым результатом,
булевы/даты/проценты вместо номера, некорректный ZIP/OOXML, размер и число строк,
внешние отношения, DTD, макросы, небезопасные пути и неизменяемость завершённого импорта.
Проверены наряды с несколькими бригадами, дедупликация людей, снимки, ввод факта и
подтверждения без наряда, неизменность нормативно-весового прогресса.

Дополнительно: `compileall`, `bash -n start.command`, `git diff --check`.
requirements, Python-минимум и скрипт запуска не менялись.

## SQLite и сохранность

Новая миграция: **009_personnel_import.sql**. Миграции **001–008 не изменены**;
контрольные суммы сверены с состоянием до разработки.

Добавлены 10 таблиц:

| Таблицы | Назначение |
| --- | --- |
| contractor_projects | Доступность одной организации на разных объектах |
| employee_projects, employee_project_periods | Постоянная связь человека с объектом и периоды доступности |
| specialty_name_keys | Сопоставление специальностей без дублей из-за регистра/пробелов |
| brigades, brigade_assignments | Постоянные бригады и история состава |
| personnel_import_sessions, personnel_import_rows | Контекст, этапы, решения и результат импорта |
| personnel_import_mappings | Подтверждённые сопоставления строк со стабильными ID |
| personnel_import_log | Действия и количества без ФИО в техническом журнале импорта |

Расширены `employees` (даты/признак старой неполной карточки) и
`work_order_crew_members` (ID и снимок номера бригады). `employees` и
`work_orders` безопасно перенесены через временные таблицы для изменения старых
составных FK: доступность на объекте теперь независима от места создания.
Существующие ID, значения, индексы, триггеры, события и снимки сохранены.
Новых журналов выполненных объёмов нет.

На временной базе 008 с людьми, выданным нарядом и событиями проверены:
Backup API → целостность копии → транзакционная 009 → сравнение всех прежних
столбцов всех таблиц → integrity_check/FK_check. Сохранились 60% / 45%, все ID,
имена в выданном документе и события. Повторная миграция не создаёт новых записей
или бэкапов. SQL-ошибка и искусственное изменение прежних данных откатывают
**схему и данные**, сохраняя проверенную резервную копию и включённые FK.

три корпуса, 15 кодов, без этажей, планов, нарядов и событий. Он **не мигрировался
и не использовался для тестов**. Его SHA-256 и время изменения сохранены:

## Работа и обновление на Mac

Остановите прежний сервер. Обновите исходники, сохраняя свою `data/` и `.venv`.
Новые зависимости не требуются. В Terminal из каталога установки:

```bash
./start.command --check
./start.command --test-db
```

После отдельной приёмки завершите сервер и запустите рабочую базу:

```bash
./start.command
```

Для начала импорта: выбрать объект → **Персонал → Импорт Excel** → подрядчик →
загрузить книгу → проверить кандидатов и решения → просмотр → подтвердить.
[Скачать шаблон](templates/Construction_Progress_4_1_Шаблон_импорта_работников.xlsx).

[Подробная архитектура, правила, восстановление и чек-лист Safari](stage41_personnel_import.md).
Миграция делается автоматически с бэкапом; при ошибке прежняя база остаётся
согласованной. Не запускайте старый код с новой схемой и не удаляйте файл базы.

## Ограничения

Новая версия **не проверялась на реальном Mac**. Приёмка предыдущих версий
пользователем не подтверждает 4.1 на Catalina Intel, современных Intel/Apple Silicon
и Safari. Нужна отдельная ручная приёмка по указанному чек-листу.

Поддерживается обычный `.xlsx`, 5 МиБ / 5000 строк. Формулы и внешние отношения
отклоняются; расширенные варианты OOXML, .xls/.xlsm и шифрованные книги не
поддерживаются. Утерянный Excel ведущий ноль без текстового формата/маски не
восстанавливается. Повтор уже подтверждённого файла показывает прежний результат;
для новых изменений нужна новая редакция книги или ручная операция.

Старые неполные карточки сохраняются и требуют явного дозаполнения. Нет
автоматического слияния людей/организаций или исправления закрытых назначений.
Справочники пока без пагинации. Персонал общий у явно открытого подрядчика;
архивирование карточки действует на все его объекты. Нет пользователей/ролей
и шифрования SQLite. Защита компьютера, персональных данных, импортной истории
и копий обеспечивается также организационными средствами. Табель, зарплата,
производительность и контроль переносов между нарядами отсутствуют.
